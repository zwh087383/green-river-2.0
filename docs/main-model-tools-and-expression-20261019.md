## 结束判断的实现

正常流程现在是：识别 → 检索/复用检索预取 → 主模型直接流式输出文字和 PCM。已移除独立 `qwen3.7-flash` 结束判断请求。

主模型 `qwen-audio-3.1-realtime-plus` 注册唯一工具 `end_conversation(reason)`。提示词和工具定义在 `src/rag_system/generation/turn_control.py`，主模型系统提示词在 `src/rag_system/generation/service.py`。

- 用户明确希望结束整段对话且没有新需求：主模型先调用工具；应用验证完整调用、身份和参数，返回 `{"end_session":true,"reason":"…","status":"finish_after_playback"}`；将结果写回同一个 WebSocket 会话后，由主模型生成简短告别语。
- 用户继续提问、单纯感谢、询问告别词含义、引用“再见”，或者告别后又提出新需求：不调用工具，正常回答。
- 未收到有效工具调用，系统不会靠关键词、回答文字或控制标记自行结束。复测曾观察到“口头道别但漏调用”，现已在工具说明和系统提示词中强调必须先调用，并加入正反示例；修正后对该句连续 5 次复测通过。只收到部分参数、错误工具名、错配身份或未完成响应，都不能提交结束结果。限制每轮最多执行一次结束工具，避免工具递归。
- 服务会发送后续 meta 更新和 final 结果，网页、ROS 网关均能识别工具决定；告别 PCM 播放完后才回到唤醒词监听。
- 结束工具是会话控制，不代表普通问题的答案已经讲完。检索仍在主模型调用之前执行，告别句也会经过检索；旧版的“前置识别告别后跳过检索”路径已移除。

实现按照[阿里云 Qwen-Audio 工具调用协议](https://help.aliyun.com/zh/model-studio/qwen-audio-realtime-user-guides)：注册 tools、接收完整 function call、写回 function_call_output、触发同会话后续回复。

## 表情修复

8 种动态表情素材及渲染代码都存在。此次补全了触发和传递：

1. 扩展共享语境规则：夸奖、安慰、志愿参与、鼓励、成果，以及明确要求某种表情。用户难过时使用关切表情。
2. 模型异步补充分析返回中性时，保留已触发的语境表情；明确指定的表情不会被回答里偶然出现的“开心”等词覆盖。
3. 回答流增加 emotion 事件，网页和 ROS 网关都接收，机器人显示节点也能保留这类表情。识别、思考和错误状态仍保持原有优先级。
4. 系统提示词明确告诉主模型：小绿有动态像素表情屏，用户要求展示表情时自然配合，避免回答“无法展示”。

普通无明显情绪的事实讲解仍可使用中性表情，不随机轮播情绪。可直接验证：“小绿你真可爱”“鼓励我”“我很难过”“展示惊讶的表情”“展示自豪的表情”。

工控机真实网页请求“展示害羞的表情”已经验证，回复为“嘿嘿，有点不好意思啦！……”；实际显示器截图保存在 `data/runtime/ipc-expression-shy-20261019.png`。8 种表情到显示页的传递及动画帧变化另外通过浏览器回归测试。

前后均在工控机内串行测试，使用同一段“介绍一下绿色江河”录音，16 kHz PCM16、100 ms 帧、实时发送，**断句均保持 800 ms**，同一个已索引知识库。以录音中估计的说话末端到首段 PCM 到达为完整链路指标；不包含扬声器实际出声、实体麦克风和唤醒过程。
