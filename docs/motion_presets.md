# 预设动作调试

机器人页面：`http://localhost:8001/#motions`。调试页读取同一动作目录，逐个执行一次；新建条目后点“刷新动作目录”即可显示。

## 现场使用

先通过原有上电按钮上电并归位，再到动作调试页选择动作。测试要求双臂在 SDK 的 A / PresetPosition 起始位，且服务空闲、双臂上电反馈有效。每次完成后回到该起始位。忙碌、断电、故障、状态失联时禁用测试；回执不明时不会自动重发。

飞吻按提供的两张图录入左右各 7 个关节角，单位为度，顺序为 L1–L7、R1–R7：起始位到第一帧速度倍率 0.5，第一帧到第二帧 0.6，第二帧回起始位 0.5。自定义帧保持当前手型。关节范围符合厂商 URDF；运动路径仍需现场测试，软件验证不会自动执行飞吻。

## 增加动作

编辑 `config/motion_presets.json`，在 presets 数组追加独立 id 的条目，例如：

```json
{
  "id": "example_action",
  "name": "示例动作",
  "type": "sequence",
  "description": "按实际采集的数据填写关节角。",
  "timeout_s": 30,
  "frames": [
    {
      "name": "关键帧 1",
      "left_arm": [0, 0, 0, 0, 0, 0, 0],
      "right_arm": [0, 0, 0, 0, 0, 0, 0],
      "scale": 0.5,
      "wait_ms": 0
    },
    {"name": "回到起始位", "home": true, "scale": 0.5}
  ]
}
```

示例中的零值仅说明格式，需替换为现场采集值。每个关键帧需提供左右臂各 7 个关节角、到达该帧的速度倍率以及可选停留时长。最后一帧必须 home:true。倍率允许 0.05–1，停留 0–5000 毫秒，单动作最多 32 帧，超时 5–120 秒。

目录每次读取；无需为新增动作修改前端或重新编译。运行请求携带页面目录 revision，目录变更后旧页面拒绝执行并要求刷新。原生层接收预设 id，从受信任目录读取不可变快照，不接收浏览器任意关节角。

## 执行链路与验证

页面 → Web 校验目录版本及厂家关节限位 → Unix socket PRESET → 已有 native SDK 宿主 → ArmControl.moveArm。角度在原生入口统一转换为弧度。左右臂每帧都需到达目标并连续检测静止才进入下一帧；故障、超时、断电或进程停止时不继续后续帧。SDK 内置动作保留原速度配置，通过原有 ArmMotion 调用，测试结束后调用 SDK 归位。

模拟 SDK 测试覆盖帧顺序、角度换算、倍率、结束归位、前置状态和故障停止。`tests/browser/verify_motion_presets_ui.py` 用隔离 HTTP 模拟服务和 headless Chrome 检查实际页面可见、目录卡片、单次提交和完成反馈，绝不连接实机动作接口。
