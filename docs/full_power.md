# 双臂与躯干统一电源

程序启动时通过厂商 SDK 使能双臂与躯干六轴。双臂归到原 A / PresetPosition；身体采用 SDK teach_script/teach_arm_config_init_pose.yaml 中“初始姿势”的 trunk_position。现场颈部有胶带垫片，用户确认其阻挡低头，因此将原始俯仰 -22° 改为 0°，避免挤压垫片；实际默认目标为 [-45, -81, -36, 0, 0, 0]°，顺序是脚踝、膝关节、大腿、腰部、转头、俯仰。程序启动和全部上下电归位统一使用这个屈膝初始姿态。配置须包含唯一一帧与六个有限数值，目标在启动前按厂商 URDF 检查，不回退到 StandUp 站直位。躯干归位倍率 0.2；双臂仍使用 SDK 已配置速度。驱动故障保护保留，故障后不自动重试。

对话页保留“仅双臂”按钮和原 /api/robot/motion/power 接口，新增“全部电源”按钮和 /api/robot/motion/all-power 接口。全部范围是双臂和六轴躯干，不包含底盘车轮。两组操作共用同一原生请求队列，动作中拒绝冲突操作；请求按 token 去重，未知回执不重试。

全部断电：只让仍使能的部位归位，不重新使能已断电的双臂；位置确认后，让躯干六轴退出使能、核对六轴使能反馈和腰腿四轴抱闸，再调用原有双臂断电。任一步失败锁定故障，不继续下电其余部位，不自动恢复。SDK 的躯干“断电”是退出使能，保留供电与通信，才能继续读取实际位置与电源反馈。

躯干使用 TrunkControl 官方连接、位置、运动、抱闸及 switchPowerOn 全六轴接口。harmonic_getStatusWord 只用于读取同一进程已打开总线的真实使能状态，不另开连接或直接写电机控制字。颈部两轴包含在六轴中；肩关节包含在双臂各七轴中。

SDK 原 trunk_control_node 由 SDK launch 自动重生。为避免出现两个硬件控制者，安装时将原文件备份为 SDK install/lib/trunk_control/trunk_control_node.greenriver-original，并在原路径安装轻量启动器，运行同目录 greenriver-trunk-owner-idle.py。这个 vendor launch 占位进程不访问硬件；项目的原生 SDK 宿主统一持有双臂与躯干控制。项目启动前必须验证占位启动器及副本完整，并确认原始躯干宿主已退出。恢复原厂躯干节点需先停止项目宿主，再从备份恢复可执行文件；禁止同时运行两个硬件所有者。

STATUS 新增 trunk：六轴 power（0 使能、1 退出使能）、positions_deg、brakes（0 抱闸）、default_deg、at_home。原双臂 power 字段保留。页面只读状态不触发电源操作，只有明确点击才提交一次请求。

“仅双臂”面板新增“重启手臂”，使用独立 POST /api/robot/motion/restart 接口，在原生控制队列中以 POWER token restart 执行。已上电时先归位、确认双臂断电、等待 0.5 秒、重新连接上电并归位；已断电时直接上电并归位。全过程不下发躯干位置或电源命令，期间拒绝其他动作和刷新归位请求；故障或超时锁定，不自动重试。双臂重新上电且位置反馈确认后才显示完成。

故障状态下“重启手臂”也可点击。请求保留原故障锁定并以 restart_pending 标识等待，直到旧 SDK 调用退出，同一个硬件控制线程才开始恢复，绝不并行启动另一个控制者。等待最多 60 秒，未退出则明确失败，不强制复位。恢复前读取真实电源与位置，拒绝急停、安全门、未知反馈或仍在运动的双臂；通过连续采样确认停止后，跳过无法执行的故障前归位，在当前位置断开双臂连接并确认断电，等待 0.5 秒后重新连接、上电和归位，最后恢复正常任务处理。恢复失败继续锁定，每次新的尝试都需要明确点击，不自动重试。整个恢复过程保留躯干连接和原有姿态。
